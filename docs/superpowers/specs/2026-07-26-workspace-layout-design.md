# GenImage 工作台布局与持久化设计

## 目标

将现有双栏工作台调整为“左侧参数设置 + 中间作品画布 + 中间底部固定创作台”。参考图片区域固定在提示词输入框上方。批量提示词不再出现在前端，但现有前端状态、请求字段和后端接口保持兼容。

后端使用 SQLite 持久化服务商配置与生成、分析历史。用户可以输入 API Key 和自定义模型名称；提供商名称固定，Base URL 固定为 `https://sub.beibeihai.xyz/v1`，暂不允许修改。历史图片以 BLOB 形式保存在数据库中。

## 页面结构

### 左侧参数设置

左侧继续使用现有黄色控制面板，容纳与单次生成相关的参数：

- 固定提供商
- 自定义模型名称
- API Key 配置
- 只读 Base URL
- 细节级别
- 每条生成数量
- 历史记录列表

左侧不再展示提示词、批量提示词、参考图片上传和生成操作。

### 中间作品画布

中间上方保留作品墙标题、生成状态、图片分析结果、生成图片列表和空状态。画布底部增加足够的安全间距，确保滚动到最后一张图片时不会被固定创作台遮挡。

### 底部固定创作台

创作台仅固定在中间作品区域底部，不覆盖左侧参数面板。其内容从上到下排列：

1. 参考图片区域：未上传时显示紧凑上传入口，上传后显示缩略图、文件名、移除按钮和“分析图片”操作。
2. 提示词区域：显示提示词输入框、生成按钮和生成中的取消状态。
3. 错误信息：与当前操作相邻显示，避免错误出现在远离触发位置的左侧。

创作台沿用现有硬边框、黄色、珊瑚红和青绿色视觉系统，不照搬参考图的品牌、深色主题和装饰元素。

## 交互与数据流

- 提示词继续绑定现有 `prompt` 状态，生成逻辑和默认提示词行为不变。
- 参考图片继续绑定现有文件与预览状态，上传、移除和分析逻辑不变。
- 生成按钮继续支持“生成图片”和“取消生成”两种状态。
- 批量提示词控件从模板中移除，但 `batchPrompts` 状态、请求中的 `prompts` 字段和后端处理保持不变。
- 设置接口只允许更新 API Key 和模型名称。API Key 留空时保持数据库中的现有值。
- 保存设置后刷新服务商注册表与模型选项，不重启后端。
- 点击历史记录时加载详情，并在中间作品画布中恢复生成图片或分析结果。

## 持久化架构

使用 `aiosqlite` 提供异步 SQLite 访问，并通过独立 Repository 层隔离 SQL 与 API、服务逻辑。应用启动时创建数据库文件 `backend/data/genimage.db` 和所需表；数据库文件加入 `.gitignore`，不进入版本控制。

配置和历史写入使用短事务。API 层负责输入输出，服务层负责生成与分析，Repository 层负责持久化；服务商客户端从数据库配置构建，并在配置更新后清理缓存。

### 配置表

`settings` 使用固定主键保存单个本地用户的配置：

- `id`：固定为 `1`
- `provider_name`：固定服务商名称
- `base_url`：固定为 `https://sub.beibeihai.xyz/v1`
- `model`：用户自定义模型名称
- `api_key`：本地明文 API Key
- `updated_at`：最后更新时间

后端启动时插入默认行；后续更新语句只修改 `model`、`api_key` 和 `updated_at`。响应永远不包含 API Key，只返回 `api_key_configured`。

### 历史表

`history` 保存每次生成或分析任务：

- 类型、状态和创建时间
- 提示词、提供商、模型、细节级别和生成数量
- 分析文本、总耗时和错误信息
- 请求完成时间

任务开始时先插入 `pending` 记录，成功后更新为 `completed`，失败后更新为 `failed` 并保存可展示的错误。失败记录也保留在历史列表中。

`history_images` 保存任务关联图片：

- 历史记录外键
- 图片角色：参考图或生成结果
- MIME 类型、原始文件名和展示顺序
- 图片二进制 BLOB

生成结果为 Base64 时直接解码入库；结果为远程 URL 时由后端下载后入库。历史详情通过独立图片接口流式返回 BLOB，不在历史列表中嵌入 Base64。

## API 设计

- `GET /api/settings`：返回固定提供商、只读 Base URL、自定义模型和 API Key 配置状态。
- `PUT /api/settings`：只接受模型名称和可选 API Key。
- `GET /api/history`：按创建时间倒序返回历史摘要。
- `GET /api/history/{history_id}`：返回单条历史详情和图片资源地址。
- `GET /api/history/{history_id}/images/{image_id}`：返回数据库中的图片内容。

本阶段不提供删除接口。历史表和图片表使用稳定主键及外键，后续可以增加单条或批量删除，并在事务中级联清理图片。

## 响应式行为

桌面端使用固定左栏和可滚动中间画布，创作台吸附在中间区域底部。窄屏下取消固定定位，页面按“参数设置、作品画布、参考图片、提示词”的顺序自然排列；创作台不覆盖结果，也不产生横向滚动。

## 错误与状态

- 服务商加载错误、生成错误和分析错误统一显示在底部创作台。
- 生成计时继续显示在作品画布标题区域。
- 分析按钮仅在已选择参考图片且当前没有其他任务时启用。
- 生成或分析过程中保持现有禁用与取消行为。
- 历史加载失败不清空当前画布，并在历史区域显示可恢复的错误状态。
- 数据库写入失败返回结构化错误，不把 API Key、SQL 或内部路径暴露给前端。

## 验证

- 运行前端生产构建，确认 Vue 模板和样式编译通过。
- 在桌面视口检查左栏、作品画布和底部创作台不重叠。
- 在窄屏视口检查创作台回到文档流，所有控件可见且文本不溢出。
- 验证上传、移除参考图片、分析图片、生成和取消生成操作仍能触发原有逻辑。
- 验证页面中不再出现批量提示词控件，后端测试保持通过。
- 验证设置重启后仍存在，Base URL 和提供商名称不能通过接口修改，API Key 不会回显。
- 验证成功和失败任务均产生历史记录，生成图片与参考图片可从 SQLite BLOB 正确读取。
- 验证历史列表不返回图片 Base64，历史详情可以恢复结果到作品画布。
