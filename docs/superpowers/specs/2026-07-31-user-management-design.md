# 用户管理与个人数据隔离设计

## 背景

GenImage 当前使用一份全局设置和一份全局历史记录。需要增加用户名密码账户体系，使 API Key、模型设置、生成记录和分析记录按用户隔离。

## 已确认规则

- 使用服务端持久化会话 Cookie。
- 注册成功后立即创建会话并自动进入工作台。
- 会话有效期为 30 天。
- 用户名只要求非空和唯一，不限制字符类型或长度。
- 密码至少 6 位。
- 注册和修改密码都需要输入两次密码确认。
- 密码使用 bcrypt 哈希存储，数据库不保存原始密码。
- 用户 API Key 按要求明文保存；接口和前端不回显完整 Key，只显示是否已配置。
- 旧的全局 API Key、全局设置和全局历史记录不迁移，数据库升级时直接删除。

## 架构

后端使用 FastAPI 认证依赖读取 `HttpOnly`、`SameSite=Lax` 的 Cookie。Cookie 中只保存不可预测的随机会话令牌，数据库保存令牌哈希、用户 ID 和过期时间。开发环境允许 HTTP；生产环境启用 `Secure`。

使用服务端会话的原因是退出登录和修改密码可以立即撤销会话，不需要等待 JWT 自然过期。修改密码后撤销该用户全部会话，避免旧设备继续使用旧登录态。

## 数据模型

### users

- `id`：主键
- `username`：唯一、非空
- `password_hash`：bcrypt 哈希
- `api_key`：可空明文
- `model`：用户自己的模型配置
- `created_at`、`updated_at`

### user_sessions

- `id`：主键
- `user_id`：关联 `users`
- `token_hash`：会话令牌哈希
- `expires_at`：创建后 30 天
- `created_at`

### history

增加 `user_id` 外键。所有创建、列表、详情和资源读取都必须绑定当前用户 ID。

### history_images

继续通过 `history_id` 关联历史记录；读取图片前先确认所属历史记录属于当前用户。

数据库初始化升级时删除旧的 `settings`、`history` 和 `history_images` 表，再创建新结构，不迁移旧数据。

## HTTP 接口

- `POST /api/auth/register`：接收用户名、密码和确认密码，校验后创建用户与会话。
- `POST /api/auth/login`：校验用户名和密码并创建会话。
- `POST /api/auth/logout`：撤销当前会话并清除 Cookie。
- `GET /api/auth/me`：返回当前用户名和 API Key 是否已配置。
- `PUT /api/auth/password`：接收旧密码、新密码和确认新密码；成功后撤销该用户全部会话。
- `GET/PUT /api/settings`：读取或修改当前用户的模型和 API Key。
- 原有生成、分析、历史与历史图片接口全部要求登录并使用当前用户 ID。

接口错误统一使用现有错误响应格式，覆盖用户名已存在、用户名为空、密码不足、密码不一致、登录失败、旧密码错误和未登录访问等情况。

## 前端流程

- 未登录访问工作台显示登录页。
- 登录页提供登录和注册入口。
- 注册页提供用户名、密码和确认密码；注册成功后直接进入工作台。
- 工作台展示当前用户名，并提供退出登录、修改密码和 API Key 配置。
- API Key 输入框默认留空；已配置时仅显示配置状态。输入新值覆盖，输入空值清除。
- 历史列表只展示当前用户记录。
- 任一受保护请求返回 `401` 时清理前端状态并跳转登录页。

## 测试

后端覆盖：注册与自动登录、重复用户名、空用户名、密码长度和一致性、登录失败、未登录保护、退出登录、修改密码及会话撤销、用户配置隔离、历史记录与图片归属校验、旧全局数据删除。

前端覆盖：登录页、注册页、注册后进入工作台、账户设置、退出登录、修改密码和 `401` 跳转。

## 安全边界

- 密码永不以明文或哈希形式返回客户端。
- API Key 永不通过响应回显完整值，仅返回布尔配置状态。
- 历史列表、详情和图片资源均在后端按用户归属校验。
- 会话令牌只通过 Cookie 传输，服务端数据库只保存其哈希值。
