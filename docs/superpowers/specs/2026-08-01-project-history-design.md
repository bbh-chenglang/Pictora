# 项目历史记录设计

## 目标

为 GenImage 增加用户级项目管理，让生成和分析历史记录归属于当前项目。用户可以在左侧项目列表中创建、选择、重命名和删除项目，也可以批量删除项目内的历史记录。删除项目或历史记录必须二次确认。

## 用户体验

工作台采用顶部栏、左侧项目栏和主创作区三段布局。顶部栏删除旧的“历史记录”按钮及右侧历史抽屉，历史入口统一放在左侧项目栏。

左侧项目栏包含“项目”标题、新建项目按钮和项目列表。项目行显示文件夹图标、项目名称及操作菜单。首次初始化用户时自动拥有名称为“第一个项目”的项目，并将其设为当前项目。

选中项目后，在项目行下显示该项目的历史记录摘要。历史记录按最近更新时间倒序排列。项目有超过 5 条历史记录时，默认只显示最近 5 条，并显示展开控制；展开后显示全部记录，再次操作可收起。项目没有历史记录时显示空状态。

每条历史记录支持勾选。选中一条或多条后显示批量删除操作。单条删除和批量删除都打开确认弹窗，弹窗明确显示将删除的记录数量，取消不会改变当前选择。

项目操作包括重命名和删除。重命名使用项目名称输入弹窗，名称不能为空且长度限制为 1 到 80 个字符。删除项目打开确认弹窗，显示项目名称及其历史数量；确认后删除项目、其全部历史和历史图片，并自动切换到其他项目。删除最后一个项目时，系统先创建新的“第一个项目”再完成切换，始终保证用户至少有一个项目。

工作区提供“新建对话”操作。该操作清空当前生成结果、分析内容、参考图片、提示词和当前历史详情，但保留当前项目选择；它不会删除历史记录。切换项目只改变当前项目和左侧历史列表，不会删除任何数据。

## 数据模型

新增 `projects` 表：

```sql
CREATE TABLE projects (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name TEXT NOT NULL,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE UNIQUE INDEX idx_projects_user_name ON projects(user_id, name);
CREATE INDEX idx_projects_user_updated ON projects(user_id, updated_at DESC, id DESC);
```

`history` 增加 `project_id INTEGER`，并建立 `(project_id, created_at DESC, id DESC)` 索引。迁移旧数据库时，为每个用户创建“第一个项目”，将该用户现有历史记录全部回填到该项目；迁移完成后新记录必须带有项目 ID。

历史图片继续由 `history_images` 通过 `history_id` 关联。删除项目时依赖项目到历史、历史到图片的级联关系，或在同一个数据库事务内按项目、历史、图片顺序删除，确保不会留下孤立图片。

## API

新增项目接口：

- `GET /api/projects`：返回当前用户的项目及每个项目的历史摘要列表。
- `POST /api/projects`：创建项目，返回项目详情。
- `PATCH /api/projects/{project_id}`：重命名项目。
- `DELETE /api/projects/{project_id}`：删除项目及其历史和图片。
- `DELETE /api/projects/{project_id}/history`：按 JSON body 中的 `history_ids` 批量删除历史。

所有接口只允许访问当前会话用户的数据。不存在、无权限或不属于当前项目的记录统一返回明确的业务错误。生成和分析请求增加必填 `project_id`，服务层在写入历史前校验项目归属。

现有历史详情和历史图片接口保留兼容，但详情查询必须验证当前用户对历史所属项目的访问权限。旧的全局 `/api/history` 列表接口不再被前端调用；如果保留后端路由，只返回当前用户数据以兼容旧客户端。

## 前端状态与组件边界

`App.vue` 负责当前项目 ID、项目列表、项目操作弹窗和新建对话状态；项目列表展示使用独立的 `ProjectSidebar` 组件，项目操作确认使用 `ConfirmDialog` 组件，项目名称输入使用 `ProjectDialog` 组件。历史摘要只保留列表需要的字段，打开历史时再请求详情。

生成和分析请求都携带当前 `project_id`。项目切换后刷新生成区为空状态和项目历史摘要；历史打开后加载详情并恢复原有工作区行为。请求过程中禁止删除正在加载的项目或记录，失败时恢复操作按钮并保留用户选择。

## 错误与删除安全

删除确认弹窗使用明确的取消和危险确认按钮，点击遮罩或 Escape 等同于取消。批量删除没有选中项时不显示删除操作。删除项目期间显示进行中状态，成功后切换项目并刷新列表；失败时保留原项目和历史列表并显示错误。

服务端删除操作使用事务。任何项目 ID、历史 ID 或用户 ID 不匹配都不能删除数据。所有删除接口都需要认证；请求体中的 ID 列表去重并限制数量，避免异常大的批量请求。

## 测试范围

后端测试覆盖：数据库迁移创建默认项目并回填旧历史；项目按用户隔离；项目创建、重命名和列表排序；项目删除级联历史及图片；批量删除只删除当前项目的选中历史；生成和分析写入指定项目；最后一个项目删除后的默认项目恢复；未认证或越权访问返回错误。

前端测试覆盖：默认显示“第一个项目”；创建、选择和重命名项目；项目历史嵌套显示；第 6 条历史默认折叠且可展开；单条和批量删除均需确认；项目删除确认后切换项目；新建对话清空工作区但保留项目；顶部不再渲染旧历史按钮和抽屉。
