# OpenAI 生成图片接口文档

本文根据项目中的官网页面副本 [`docs/genimage.md`](./genimage.md) 整理，并使用 OpenAI 官方 Images API Reference 核对请求字段。

文档重点说明如何使用 `gpt-image-2` 进行文生图。若只需要根据一段提示词生成一张或多张图片，优先使用 **Images API**；只有在需要对话式、多轮生成或连续编辑时，才建议使用 **Responses API**。

## 1. 最简调用方式

### 1.1 接口信息

| 项目 | 内容 |
| --- | --- |
| 请求方法 | `POST` |
| 请求地址 | `https://api.openai.com/v1/images/generations` |
| 鉴权方式 | `Authorization: Bearer $OPENAI_API_KEY` |
| 请求类型 | `Content-Type: application/json` |
| 推荐模型 | `gpt-image-2` |
| 默认返回 | Base64 编码的图片数据，位于 `data[].b64_json` |

使用 GPT Image 模型前，OpenAI 可能要求先完成 API Organization Verification。

### 1.2 cURL 示例

```bash
curl -X POST "https://api.openai.com/v1/images/generations" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "prompt": "一张儿童绘本风格的插画：兽医用听诊器倾听小水獭的心跳",
    "size": "1024x1024",
    "quality": "medium",
    "output_format": "png",
    "n": 1
  }'
```

接口不会直接返回图片文件。GPT Image 模型返回 `data[0].b64_json`，需要先进行 Base64 解码，再保存为对应格式的文件。

### 1.3 Python SDK 示例

```python
import base64
from openai import OpenAI

client = OpenAI()  # 默认读取环境变量 OPENAI_API_KEY

result = client.images.generate(
    model="gpt-image-2",
    prompt="一张儿童绘本风格的插画：兽医用听诊器倾听小水獭的心跳",
    size="1024x1024",
    quality="medium",
    output_format="png",
    n=1,
)

image_bytes = base64.b64decode(result.data[0].b64_json)
with open("output.png", "wb") as file:
    file.write(image_bytes)
```

安装 SDK：

```bash
pip install openai
```

### 1.4 JavaScript SDK 示例

```javascript
import fs from "node:fs";
import OpenAI from "openai";

const openai = new OpenAI(); // 默认读取环境变量 OPENAI_API_KEY

const result = await openai.images.generate({
  model: "gpt-image-2",
  prompt: "一张儿童绘本风格的插画：兽医用听诊器倾听小水獭的心跳",
  size: "1024x1024",
  quality: "medium",
  output_format: "png",
  n: 1,
});

const imageBytes = Buffer.from(result.data[0].b64_json, "base64");
fs.writeFileSync("output.png", imageBytes);
```

安装 SDK：

```bash
npm install openai
```

## 2. Images API 完整入参

下面是 `POST /v1/images/generations` 的完整请求字段。字段兼容性会随模型而变化，因此表中单独标出了 `gpt-image-2` 的传法。

| 参数 | 类型 | 必填 | `gpt-image-2` 建议传法 | 说明 |
| --- | --- | --- | --- | --- |
| `prompt` | `string` | 是 | 直接传图片描述，最长 32,000 字符 | 描述希望生成的图片。可包含主体、环境、构图、风格、光线、文字和限制条件。 |
| `model` | `string` | 否 | 建议显式传 `"gpt-image-2"` | 不显式传模型可能使用接口默认模型，不建议依赖默认值。 |
| `n` | `integer` | 否 | `1` 到 `10`，通常传 `1` | 一次请求生成的图片数量，默认为 `1`。图片越多，费用和响应体越大。 |
| `size` | `string` | 否 | `"auto"` 或合法的 `"宽x高"` | 输出尺寸；`gpt-image-2` 支持满足约束的任意分辨率。`auto` 为默认值。 |
| `quality` | `string` | 否 | `"auto"`、`"low"`、`"medium"`、`"high"` | 输出质量，默认为 `auto`。草稿建议 `low`，最终素材可用 `medium` 或 `high`。 |
| `output_format` | `string` | 否 | `"png"`、`"jpeg"`、`"webp"` | GPT Image 的输出文件格式，默认 `png`。追求速度或较小体积时优先考虑 `jpeg`。 |
| `output_compression` | `integer` | 否 | `0` 到 `100` | 仅对 `jpeg`、`webp` 生效；API Reference 标注默认值为 `100`。不要与 `png` 一起依赖此参数。 |
| `background` | `string` | 否 | `"auto"` 或 `"opaque"` | 通用 GPT Image 接口还定义了 `transparent`，但原文明确说明 `gpt-image-2` 当前不支持透明背景。 |
| `moderation` | `string` | 否 | `"auto"` 或 `"low"` | 内容审核强度。`auto` 为默认标准过滤；`low` 为限制较少的过滤。仍会受内容政策约束。 |
| `stream` | `boolean` | 否 | `true` 或 `false` | 是否使用流式图片生成，默认 `false`。仅 GPT Image 模型支持。 |
| `partial_images` | `integer` | 否 | `0` 到 `3` | 流式生成时希望收到的中间图数量。应与 `stream: true` 一起使用。每张中间图会产生额外图片输出 token。 |
| `user` | `string` | 否 | 传业务侧稳定、非敏感的用户标识 | 用于帮助 OpenAI 监控和识别滥用。不要传姓名、手机号等直接个人信息。 |
| `response_format` | `string` | 否 | **不要传** | 仅 DALL·E 2/3 使用，可选 `url` 或 `b64_json`。GPT Image 始终返回 Base64，不支持该参数。 |
| `style` | `string` | 否 | **不要传** | 仅 DALL·E 3 使用，可选 `vivid` 或 `natural`。GPT Image 不支持。 |

推荐的普通请求体：

```json
{
  "model": "gpt-image-2",
  "prompt": "产品摄影：一只白色陶瓷咖啡杯放在浅色木桌上，柔和自然光，干净背景，正方形构图",
  "n": 1,
  "size": "1024x1024",
  "quality": "medium",
  "output_format": "png",
  "background": "auto",
  "moderation": "auto"
}
```

## 3. 重点参数怎么传

### 3.1 `prompt`

`prompt` 是唯一明确必填的业务字段。对 GPT Image 模型最长可传 32,000 字符。

建议按以下信息组织提示词：

1. 主体：画面中有什么。
2. 场景：主体所处环境、时间和天气。
3. 构图：景别、机位、主体位置和画幅方向。
4. 风格：摄影、插画、3D、油画等。
5. 光线与色彩：自然光、棚拍光、主色调等。
6. 精确要求：需要出现的文字、数量、材质和品牌规范。
7. 排除项：不希望出现的元素，可直接用自然语言描述。

示例：

```text
电商产品摄影：一只无品牌的白色保温杯，置于浅灰色摄影台中央；
45 度俯拍，柔和棚拍光，杯身轮廓清晰，背景干净，无人物、无文字、无水印；
纵向构图，适合作为商品详情页主图。
```

### 3.2 `size`

`gpt-image-2` 可以传 `auto`，也可以传形如 `WIDTHxHEIGHT` 的字符串，例如 `1536x864`。尺寸必须同时满足：

- 宽和高都必须是 `16` 的倍数。
- 任一边不得超过 `3840px`。
- 长边与短边的比例不得超过 `3:1`。
- 总像素数不得少于 `655,360`，不得超过 `8,294,400`。
- 超过 `2560x1440`，即 `3,686,400` 总像素的输出属于实验性能力。

常用尺寸：

| 用途 | 建议值 |
| --- | --- |
| 正方形、速度优先 | `1024x1024` |
| 横图 | `1536x1024` |
| 竖图 | `1024x1536` |
| 2K 正方形 | `2048x2048` |
| 2K 横图 | `2048x1152` |
| 4K 横图 | `3840x2160` |
| 4K 竖图 | `2160x3840` |
| 交给模型选择 | `auto` |

正方形图片通常生成得最快。尺寸越大，延迟和费用通常越高。

### 3.3 `quality`

| 值 | 适用场景 |
| --- | --- |
| `auto` | 让模型根据提示词自动选择，默认值 |
| `low` | 草稿、缩略图、快速迭代，速度最快 |
| `medium` | 一般业务图片，质量和成本相对均衡 |
| `high` | 最终素材或细节要求较高的图片，耗时和费用更高 |

### 3.4 `output_format` 与 `output_compression`

- `png`：默认格式，适合无损图片；`output_compression` 不适用。
- `jpeg`：编码通常快于 PNG，适合照片类图片，不支持透明背景。
- `webp`：适合网页使用，可配合压缩参数减小体积。
- 使用 `jpeg` 或 `webp` 时，`output_compression` 传 `0` 到 `100` 的整数。

`output_format` 决定图片字节的实际格式，保存文件时应使用匹配的扩展名。

### 3.5 `background`

接口通用取值为：

- `auto`：由模型决定，默认值。
- `opaque`：不透明背景。
- `transparent`：透明背景，只能配合 `png` 或 `webp`，但 **`gpt-image-2` 当前不支持**。

因此调用 `gpt-image-2` 时只传 `auto` 或 `opaque`。

### 3.6 `n`

取值范围为 `1` 到 `10`，默认生成一张。服务端返回的 `data` 数组通常包含 `n` 个结果：

```python
for index, item in enumerate(result.data):
    image_bytes = base64.b64decode(item.b64_json)
    with open(f"output-{index}.png", "wb") as file:
        file.write(image_bytes)
```

### 3.7 `moderation`

- `auto`：默认标准过滤。
- `low`：相对较少限制的过滤。

该参数只改变 GPT Image 模型提供的审核严格程度，并不关闭内容审核，也不绕过 OpenAI 使用政策。

### 3.8 `user`

建议传业务系统内部的稳定用户 ID，例如经过不可逆哈希或随机化后的 ID：

```json
{
  "user": "user_8f3a12c9"
}
```

不建议直接传用户姓名、邮箱、手机号或身份证号。

## 4. 返回结果与图片保存

### 4.1 非流式返回

GPT Image 模型的核心返回结构如下：

```json
{
  "created": 1750000000,
  "background": "opaque",
  "data": [
    {
      "b64_json": "iVBORw0KGgoAAA..."
    }
  ],
  "output_format": "png",
  "quality": "medium",
  "size": "1024x1024",
  "usage": {
    "input_tokens": 100,
    "output_tokens": 1000,
    "total_tokens": 1100
  }
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `created` | 生成时间，Unix 秒级时间戳 |
| `data` | 生成结果数组，对应请求中的 `n` |
| `data[].b64_json` | Base64 编码后的图片字节 |
| `background` | 最终使用的背景类型，可能不返回 |
| `output_format` | 最终图片格式，可能不返回 |
| `quality` | 最终质量档位，可能不返回 |
| `size` | 最终图片尺寸，可能不返回 |
| `usage` | token 用量信息，具体字段是否存在取决于模型和接口版本 |

注意：`data[].url` 是 DALL·E 2/3 配合 `response_format: "url"` 时的返回方式。GPT Image 不支持 `response_format`，应读取 `b64_json`。

### 4.2 Base64 解码

Python：

```python
import base64

with open("output.png", "wb") as file:
    file.write(base64.b64decode(result.data[0].b64_json))
```

Node.js：

```javascript
fs.writeFileSync(
  "output.png",
  Buffer.from(result.data[0].b64_json, "base64"),
);
```

## 5. 流式生成

流式生成适合在等待最终图片时先展示中间结果。设置：

```json
{
  "model": "gpt-image-2",
  "prompt": "雪山脚下的湖泊，清晨薄雾，电影感摄影",
  "stream": true,
  "partial_images": 2
}
```

`partial_images` 的取值为 `0` 到 `3`：

- `0`：只在流中接收最终图片。
- `1` 到 `3`：最多接收指定数量的中间图片。
- 如果最终图片生成得更快，实际收到的中间图可能少于请求数量。
- 每张中间图额外消耗 `100` 个图片输出 token。

Python 示例：

```python
import base64
from openai import OpenAI

client = OpenAI()

stream = client.images.generate(
    model="gpt-image-2",
    prompt="雪山脚下的湖泊，清晨薄雾，电影感摄影",
    stream=True,
    partial_images=2,
)

for event in stream:
    if event.type == "image_generation.partial_image":
        image_bytes = base64.b64decode(event.b64_json)
        with open(f"partial-{event.partial_image_index}.png", "wb") as file:
            file.write(image_bytes)
```

## 6. Responses API：对话式生成图片

需要多轮修改图片时，可使用 Responses API。这里的 `model` 是支持图片生成工具的主模型，不是直接指定 GPT Image 模型；图片工具负责选择实际图片模型。

### 6.1 基本调用

```python
import base64
from openai import OpenAI

client = OpenAI()

response = client.responses.create(
    model="gpt-5.6",
    input="生成一张灰色虎斑猫拥抱戴橙色围巾的水獭的图片",
    tools=[
        {
            "type": "image_generation",
            "action": "generate",
            "quality": "medium",
            "size": "1024x1024",
            "output_format": "png"
        }
    ],
)

images = [
    output.result
    for output in response.output
    if output.type == "image_generation_call"
]

if images:
    with open("response-output.png", "wb") as file:
        file.write(base64.b64decode(images[0]))
```

Responses API 的关键参数：

| 参数位置 | 参数 | 传法 |
| --- | --- | --- |
| 请求顶层 | `model` | 传支持 `image_generation` 工具的主模型，例如原文示例中的 `gpt-5.6` |
| 请求顶层 | `input` | 传用户的图片生成或修改要求，可为字符串或结构化输入 |
| 请求顶层 | `tools` | 至少包含 `{ "type": "image_generation" }` |
| 请求顶层 | `previous_response_id` | 多轮修改时传上一次响应的 `response.id` |
| 请求顶层 | `stream` | 需要流式事件时传 `true` |
| 图片工具内 | `action` | `auto`、`generate`、`edit`；默认 `auto`。纯文生图可传 `generate` |
| 图片工具内 | `partial_images` | `0` 到 `3`，配合顶层 `stream: true` |
| 图片工具内 | 输出参数 | 可配置 `size`、`quality`、`output_format`、`output_compression`、`background` 等图片输出选项，仍需遵守实际图片模型的兼容性 |

`action` 的行为：

- `auto`：由模型决定生成新图还是编辑上下文中的图片。
- `generate`：强制生成新图片。
- `edit`：强制编辑上下文中的图片；如果上下文没有图片会报错。

Responses API 返回结果位于 `response.output` 中，需要筛选 `type == "image_generation_call"`，然后读取 `result` 中的 Base64 图片。`revised_prompt` 可用于查看主模型为提升生成效果而自动改写后的提示词。

## 7. 错误处理建议

### 7.1 常见 HTTP 错误

| 情况 | 处理建议 |
| --- | --- |
| `401` / `403` | 检查 API Key、组织权限以及是否已完成 Organization Verification |
| `429` | 触发速率限制或额度限制；按响应头退避重试，并检查账户额度 |
| `5xx` | 服务端临时错误，可使用指数退避进行有限次数重试 |
| 参数错误 | 检查模型是否支持该参数、尺寸是否合法、格式与背景是否兼容 |

### 7.2 图片生成用户错误

部分请求会返回：

```json
{
  "error": {
    "type": "image_generation_user_error",
    "code": "moderation_blocked",
    "moderation_details": {
      "moderation_stage": "input",
      "categories": ["harassment"]
    }
  }
}
```

处理原则：

- 先按稳定字段 `error.code` 分支，不要只匹配错误文本。
- `image_generation_user_error` 通常需要修改提示词或输入，不能原样自动重试。
- `moderation_stage: "input"` 表示输入被拦截；`"output"` 表示生成结果被拦截；`"unknown"` 表示无法确定阶段。
- `moderation_details` 是可选字段，应主要用于日志、客服排查和修改提示，不应直接向最终用户暴露过多审核细节。
- 建议记录响应中的 request ID，便于排查接口问题。

## 9. 使用注意事项

- 复杂图片可能需要接近 2 分钟才能完成，客户端超时时间不要设置过短。
- 更大的尺寸、更高的质量以及更多的图片通常会增加成本和延迟。
- 对包含精确文字、复杂排版、固定角色或品牌元素的画面，应在业务侧预留人工检查和重试机制。
- 不要把 GPT Image 的 Base64 返回误当作可直接访问的 URL。
- 不要向 `gpt-image-2` 传 `response_format`、`style` 或 `background: "transparent"`。
- 官方参数和模型能力可能更新，上线前应再次核对当前模型页和接口参考。
