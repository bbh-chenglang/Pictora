# Pictora 视频功能：部署、接口与恢复

核对日期：2026 年 10 月 8 日（Asia/Shanghai）。本文件描述此版本的实现，不代表上游未来的模型能力或计费承诺。

## 1. 已实现的范围

- 同一工作台切换“图片 / 视频”，共用登录，图片项目与视频项目独立管理；两种模式分别保留草稿、参数、项目与历史选择。视频草稿按账号和项目保存在浏览器本地，清除浏览器数据后不保证保留。
- 独立视频 Key 管理和非付费模型连接测试。视频默认根地址为 https://direct.beibeihai.xyz，不使用图片 Key、图片服务地址或图片生成通道。
- 每次只创建一个视频任务。文生视频、图片 / 视频 / 音频参考由所选模型的已核对能力控制；不开放首尾帧、批量提示词、多视角或生成数量设置。
- 本地上传、已有生成图片的独立快照、外部 HTTPS 链接；素材可重命名并插入 @名称。切换模型保留素材，但不兼容项会阻止提交；“尚未确认”不等于支持。
- SQLite schema 19，在视频配置、素材、任务、结果及对象清理队列基础上增加项目类型 `media_type`（`image` / `video`），不复用图片 BLOB 或图片生成批次。新建项目可提交 `media_type`，省略时按图片项目处理；同名图片项目和视频项目可以并存，生成接口拒绝使用错误类型的项目。
- schema 18 升级时，有视频但没有图片历史的项目转为视频项目；同时包含图片和视频的项目拆分为两个同名、不同类型的项目，保留记录与素材。原来的空项目归入图片工作区，没有视频项目的账号进入工作台时会得到默认视频项目。后端启动自动迁移，不需要手动修改数据库。
- 视频任务卡片不展示上游 ID 和重复的上游 / 本地状态行；生成期间显示动态已用时，完成后显示总耗时。计时使用已持久化的 UTC 时间，刷新不会归零；素材兼容校验和必要错误提示仍保留。

## 2. 上线前必须先备份

**先等待当前任务完成，或明确暂停 / 放弃本地追踪，再安排停机备份。停机和放弃都不会取消上游任务，也不会触发退款。**

默认生产数据卷是 genimage_data，包含 SQLite、原有图片和视频参考文件。停止后端后再复制整个数据卷，避免只拷贝正在写入的 SQLite 主文件而漏掉 WAL：

~~~bash
# 在项目根目录执行。不要使用 down -v，也不要删除现有桶或数据卷。
docker compose stop backend
mkdir -p backups
docker run --rm \
  -v genimage_data:/data:ro \
  -v "$PWD/backups:/backup" \
  alpine:3.21 \
  tar czf "/backup/pictora-data-$(date +%Y%m%d-%H%M%S).tar.gz" -C /data .
# 留存旧代码 / 镜像版本以及原有的服务端 .env，然后再升级。
~~~

本地开发则在停掉 Uvicorn 后备份 backend/data 整个目录。备份包含用户资料、视频 / 图片 API Key 和参考素材，应按敏感数据管理。环境文件另行安全备份。

**R2 对象不包含在 SQLite / 数据卷备份中。** 必须另外安排私有桶备份；仅有数据库不能恢复已删除的 R2 对象。回滚 schema 19 前先恢复匹配版本的完整备份，不把新数据库直接交给旧代码。此升级不会自动创建公开桶、修改桶生命周期策略或删除原有图片记录。

## 3. 配置与就绪门槛

生产 Compose 读取项目根目录 .env；直接运行后端读取 backend/.env。配置示例见 backend/.env.example。R2 和签名敏感值只由后端环境变量读取，前端设置页不接收它们。

视频接口按照《视频API对接文档》使用 direct.beibeihai.xyz；图片接口继续使用 sub.beibeihai.xyz。若服务器环境变量或 .env 中显式配置了旧视频地址，必须将 VIDEO_API_BASE_URL 改为 https://direct.beibeihai.xyz；该配置会覆盖新的默认值。修改后执行 docker compose up -d --build backend 重建并重新创建后端容器；HTTPS 部署使用 docker compose -f compose.yaml -f compose.https.yaml up -d --build backend。本地直接运行则修改 backend/.env 或进程环境变量后重启后端。此地址切换无需数据库迁移，也不会自动替换已保存的 API Key；可使用非付费连接测试确认现有 Key 在新服务上是否可用。

| 环境变量 | 默认值 / 作用 |
| --- | --- |
| VIDEO_API_BASE_URL | https://direct.beibeihai.xyz，可信 HTTPS 根地址，**不含路径或查询串** |
| VIDEO_PUBLIC_BASE_URL | 空；上游访问签名素材的公网 HTTPS 源站根地址，不含路径、查询串或自定义端口 |
| VIDEO_ASSET_SIGNING_SECRET | 空；至少 32 个字符，随机、持久化保管，不要每次部署重置 |
| R2_ACCOUNT_ID | 空；R2 Account ID（32 位十六进制字符串） |
| R2_ACCESS_KEY_ID | 空；R2 S3 API Access Key ID |
| R2_SECRET_ACCESS_KEY | 空；R2 S3 API Secret Access Key |
| R2_BUCKET_NAME | 空；管理员已创建的私有桶，全站共用 |
| R2_KEY_PREFIX | pictora/videos/，对象隔离前缀 |
| VIDEO_POLL_INTERVAL | 3 秒，后台查询间隔 |
| VIDEO_MAX_WAIT | 1200 秒，单轮自动查询等待上限 |
| VIDEO_MAX_CONCURRENCY | 2，全局视频执行并发 |
| VIDEO_MAX_TASKS_PER_USER | 2，每用户本地活跃任务上限 |
| VIDEO_MAX_ACTIVE_TASKS | 32，全站待处理 / 活跃任务上限 |
| VIDEO_RESULT_MAX_BYTES | 536870912（512 MiB），单个结果下载的应用上限 |
| COOKIE_SECURE | 基础 HTTP 模式 false；HTTPS 叠加配置强制 true |

示例（占位值必须替换，不要提交凭据）：

~~~dotenv
PICTORA_DOMAIN=pictora.example.com
VIDEO_API_BASE_URL=https://direct.beibeihai.xyz
VIDEO_PUBLIC_BASE_URL=https://pictora.example.com
VIDEO_ASSET_SIGNING_SECRET=REPLACE_WITH_A_PERSISTENT_RANDOM_SECRET_OF_AT_LEAST_32_CHARACTERS
R2_ACCOUNT_ID=REPLACE_WITH_YOUR_32_HEX_ACCOUNT_ID
R2_ACCESS_KEY_ID=REPLACE_WITH_BUCKET_SCOPED_ACCESS_KEY
R2_SECRET_ACCESS_KEY=REPLACE_WITH_SECRET_KEY
R2_BUCKET_NAME=pictora-private
R2_KEY_PREFIX=pictora/videos/
~~~

- R2 桶保持私有。为后端提供该桶的对象读取、写入、删除权限以及 HeadBucket / HeadObject 所需权限；无需让终端用户配置桶，也不需要永久公开地址。
- 本应用只检查 HeadBucket 连接（成功 / 失败缓存 60 秒）。这不会创建付费视频，也不证明所有对象写入权限都正确。管理员应先用非生成的测试对象验证上传、读取、删除和签名访问权限，再考虑授权真实视频验收。
- R2 未配置或检查未通过时，禁止创建新视频，避免上游扣费后没有保存目标。
- 缺少 ffprobe 时也禁用提交：结果必须进行真实 MP4 / 媒体校验。Docker 镜像已安装 ffmpeg（包括 ffprobe）；本地 Windows 开发应把 ffprobe 放入后端进程可见的 PATH，执行 ffprobe -version 检查。
- 公网 HTTPS 地址或持久化签名密钥未配置时，仅禁用本地上传与已有图片引用；存储和媒体工具就绪后，文生视频及外部 HTTPS 素材仍可用。
- /api/videos/readiness 返回以上就绪布尔值；不会返回 R2 凭据或签名密钥。api_ready=false 表示视频服务根地址无效，不应影响图片页面或服务启动。
- 已有视频后，不要随意改 Account ID、桶名或对象前缀；数据库保存的是对象键，变更这些配置需要有计划地迁移旧对象。更换素材签名密钥会使尚未过期的旧素材链接失效，可能影响上游正在读取的参考文件。

## 4. Caddy 公网 HTTPS（可选）

原有 HTTP 开发 / 部署保持可用：基础 compose.yaml 继续在 8083 端口暴露网站。

公网上传需要真实域名、正确的 DNS 解析，以及上游可以无需登录访问签名链接的 HTTPS 服务；仅设置一个看起来像 HTTPS 的字符串不等于部署完成。不要给签名素材路径加交互登录、验证码或机器人挑战。

1. 域名解析到服务器，确保 TCP 80 / 443 可访问；配置正确的 A / AAAA 记录。不要发布不可达的 IPv6 记录。
2. 根目录 .env 设置 PICTORA_DOMAIN、VIDEO_PUBLIC_BASE_URL 和持久化签名密钥，同时完成私有 R2 配置。
3. 使用 Docker Compose **2.24.4 或更新版本**（叠加文件使用 !override 替换端口）。
4. 备份完成后手动执行部署，先检查配置，不要把含秘密的完整 compose config 输出发到聊天或公开日志：

~~~bash
docker compose -f compose.yaml -f compose.https.yaml config --quiet
docker compose -f compose.yaml -f compose.https.yaml up -d --build
docker compose -f compose.yaml -f compose.https.yaml ps
docker compose -f compose.yaml -f compose.https.yaml exec backend ffprobe -version
~~~

compose.https.yaml 启动 Caddy，反代到 web:80；证书状态保存在 caddy_data / caddy_config 卷。HTTPS 模式中 8083 仅绑定 127.0.0.1，登录使用 HTTPS 地址（Secure Cookie 不用于本地 HTTP）。当前实现不自动替你部署服务器、配置 DNS、申请 R2 桶或更改桶的生命周期。

Nginx 仅将 /api/videos/assets/upload 提升为 128 MiB 请求体容限；其他路由原有 25 MiB 限制不变。后端仍按真实文件大小执行更小的单文件限制，不能靠 Content-Type 或扩展名绕过。视频上传路径及签名素材访问日志避免记录完整签名查询串；其他外部代理也应遵守这一规则。

## 5. 模型参数与参考能力

/api/videos/models 使用当前激活视频 Key 请求 direct.beibeihai.xyz/v1/models，返回该 Key 可见的完整模型 ID、默认档位和本地已知参数。模型目录按 Key 缓存 10 分钟；模型列表只说明可见权限，最终参数能力仍以上游为准。视频工作台的“刷新”和视频设置的“同步视频模型”调用 /api/videos/models?refresh=true，立即重新读取上游。

目录暂不可用时保留上次有效目录，首次离线使用 2026-10-10 的 5 模型快照，并标记 catalog_source：live_catalog 表示成功读取；cached_live_catalog 表示最近读取失败、沿用上次实时目录；bundled_snapshot_2026-10-10 表示内置离线快照。Key 的默认模型校验与非付费连接测试也使用同一目录。已下线的草稿 / Key 模型仍显示并提示重新选择，不自动改写草稿或历史。

参考数量按已确认的模型编码规则解析：模型 ID 末尾为 `模型名-数量编码-分辨率编码`，可带 `（秒）` / `（次）` 计费后缀。三位数量编码分别表示图片、视频、音频数量，例如 `933` 为 9 / 3 / 3，`903` 为 9 / 0 / 3；六位编码每两位为一组，例如 `301010` 为 30 / 10 / 10。`0` 表示不支持该类型。上游新增的同格式模型也使用此规则；无法解析的编码仍显示“尚未确认”并阻止参考素材提交。

| 模型 | 图片 | 视频 | 音频 |
| --- | ---: | ---: | ---: |
| seedance-2.0-933-720P（秒） | 9 | 3 | 3 |
| seedance-2.0-fast-933-720P（次） | 9 | 3 | 3 |
| seedance-2.0-mini-903-720P（次） | 9 | 不支持 | 3 |
| seedance-2.5-301010-1K（秒） | 30 | 10 | 10 |
| minimax-h3-933-2K（次） | 9 | 3 | 3 |

`720P` 表示最高 720p，目录提供 `480p`、`720p`，不会允许 1080p。请求分辨率仍遵循对接文档，仅发送 `480p`、`720p`、`1080p`；模型名中的 `1K`、`2K` 不作为请求枚举值，沿用目录中的上述三个档位，实际支持组合以上游为准。

时长为 1–15 秒，默认 5 秒；比例为 16:9、9:16、1:1，默认 16:9。默认分辨率为 720p，Mini 按对接文档使用 480p。素材数量上限由前端和后端同时校验；编码没有提供额外的素材总数或参考视频总时长限制。

本应用上传限制（不是上游格式 / 体积支持承诺）：

| 素材 | 格式 | 单文件上限 |
| --- | --- | ---: |
| 图片 | PNG / JPEG / WebP / GIF，实际解码验证 | 10 MiB |
| 视频 | MP4，容器完整性 + ffprobe 流和数据包检查 | 100 MiB |
| 音频 | MP3 / WAV，ffprobe 检查 | 20 MiB |

外部链接仅接受无嵌入凭据的 HTTPS。服务器下载 / 探测时校验所有 DNS 地址属于公网并固定连接 IP，逐跳限制重定向、大小和时间；媒体客户端不带本站 Authorization 或 Cookie。超过应用限制、无效媒体或来源访问受限会阻止提交 / 保存，应明确修正，不得无限重试生成。

未引用上传素材 24 小时后清理；任务引用的素材随历史保留。删除最后一个引用该素材的任务或项目后清理相应本地文件。上传中断残留也会被清理；下载暂存文件保留 7 天的恢复窗口，超期后重试保存可能需要重新下载，但**不会重新生成**。

## 6. API 速查

除单文件签名素材入口外，以下接口要求现有 Pictora 登录会话（Cookie）并验证用户归属；跨用户访问返回不存在 / 拒绝。ID 示例仅用于说明。

### 视频配置

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET / POST | /api/settings/video-api-keys | 列表 / 新建独立视频配置 |
| PATCH / DELETE | /api/settings/video-api-keys/{config_id} | 编辑 / 删除；仍被追踪的 Key 不可删除或更换密钥 |
| PUT | /api/settings/video-api-keys/active | 选择，JSON 为 {"config_id":11} |
| POST | /api/settings/video-api-keys/{config_id}/test | GET 上游 /v1/models，只测连接，不生成 |

新建 JSON：{"alias":"视频账号","api_key":"YOUR_VIDEO_KEY","model":"seedance-2.0-933-720P（秒）"}。查询响应只给 api_key_configured，不回传密钥；编辑省略 api_key 以保留原密钥。

### 素材与目录

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/videos/readiness | 视频服务 / 本地素材 / R2 / ffprobe 状态 |
| GET | /api/videos/models | 有效模型目录与能力；refresh=true 强制同步上游 |
| POST | /api/videos/assets/upload?type=image\|video\|audio | **本应用** multipart，file 必填，name 可选 |
| POST | /api/videos/assets/from-history | {"history_id":12,"image_id":34,"name":"主角"}，验证归属后保存独立快照 |
| GET | /api/videos/assets/{asset_id}/file | 登录用户自己的素材 |
| GET | /api/videos/assets/public/{asset_id}?expires=...&signature=... | 仅当前单素材签名访问，默认 24 小时；不是公开图片库 |

### 任务与结果

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | /api/videos/tasks | JSON 创建，持久化后返回 202 |
| GET | /api/videos/requests/{request_id} | 按请求 UUID 查找当前用户的原任务，不受历史列表分页限制；返回 accepted / missing / closed |
| POST | /api/videos/requests/{request_id}/resolve | {"project_id":1}；找回已创建任务，或登记关闭尚未创建的旧请求，不触发生成 |
| GET | /api/videos/tasks?project_id=1&limit=100&offset=0 | 用户 / 项目任务列表，limit 最大 100 |
| GET | /api/videos/tasks/{task_id} | 状态、进度、素材、已保存结果 |
| POST | /api/videos/tasks/{task_id}/resume | 恢复已知上游 ID 的查询 / 保存 |
| POST | /api/videos/tasks/{task_id}/retry-save | 仅重试已生成但保存失败的任务 |
| POST | /api/videos/tasks/{task_id}/bind | {"upstream_task_id":"PUBLIC_TASK_ID"}；用原 Key 查询验证后接管不确定提交 |
| POST | /api/videos/tasks/{task_id}/abandon | 停止本地追踪，**不是上游取消，也不退款** |
| DELETE | /api/videos/tasks/{task_id} | 删除已结束或已放弃任务；私有对象进入可重试清理队列 |
| GET | /api/videos/tasks/{task_id}/results/{result_id}/play | 验证归属后 307 跳转到 10 分钟有效的 R2 签名地址 |
| GET | /api/videos/tasks/{task_id}/results/{result_id}/download | 本服务鉴权流式返回 MP4，设置文件名，支持单段 Range / 206 |

网络异常后保留的“待确认”请求可点击“核对并解除待确认请求”，或底部“核对上次提交（不生成）”。核对保留当前模型、提示词和素材；已创建的任务直接找回，未创建的旧请求在数据库登记关闭，再次使用该 UUID 提交会返回 410。核对与创建在同一个数据库写锁下执行，避免正在处理的迟到提交在解除后创建重复任务。核对完成后，再点击“生成视频”才创建新任务。

后端启动时自动创建轻量的 video_closed_requests 表，保留已有任务、视频 Key 与历史记录。关闭记录按用户隔离，即使项目后来被删除也保留，以阻止旧请求迟到；不会取消已经提交到上游的任务。

创建本地任务的示例（**此接口会触发付费生成；不要把示例当连接测试执行**）：

~~~json
{
  "request_id": "e4ae7951-8f2c-4781-a2c0-3c8b445d708d",
  "project_id": 1,
  "api_key_config_id": 11,
  "model": "seedance-2.0-933-720P（秒）",
  "prompt": "@主角 缓缓回头，镜头平稳推进",
  "duration": 5,
  "resolution": "720p",
  "ratio": "16:9",
  "materials": [
    { "type": "image", "name": "主角", "asset_id": "OWNED_ASSET_ID" },
    { "type": "audio", "name": "配乐", "url": "https://your-public-host/music.mp3" }
  ]
}
~~~

单个素材只能选择 asset_id 或 url。后端转换为上游 JSON 的 images / videos / audios 数组；不会向上游发送 multipart，也不会发送本地项目、Key 配置 ID、UUID、批量数量或未约定控制参数。

request_id 是用户范围内的 UUID。原参数 + 同一 UUID 重试会取得同一任务；不同参数使用同一 UUID 返回 409。不确定网络响应必须保留 UUID，不要换一个 UUID 盲目重新点击。前端为明确 4xx 拒绝允许修正参数；网络错误 / 5xx 保留 UUID，并提供恢复原参数入口。

## 7. 异步状态、恢复与删除

上游状态与本地状态独立保存：

| 本地状态 | 意义 / 操作 |
| --- | --- |
| queued | 持久化本地排队，尚未发起上游创建 |
| submitting | 创建 POST 正在执行；不自动重试 POST |
| running | 上游已有公开 ID，查询同一个任务 |
| polling_paused | 本轮超时 / 暂时错误 / 未识别状态，允许恢复查询；**不宣称生成失败、取消或退款** |
| submission_unknown | 创建响应不确定且没有公开 ID；核对上游控制台后手工填写 ID 验证接管，不自动再次 POST |
| saving | 上游完成，正在下载、校验、上传 R2 |
| storage_failed | 已生成但本地保存失败；重试下载 / 上传，绝不再次创建视频 |
| completed | R2 上传且大小复核成功，已保存完成 |
| failed | 上游明确失败 / 创建明确拒绝，或本地付费提交前的阻断；不能当作退款凭证 |
| abandoned | 已停止本地追踪，不取消上游；已知 ID 仍可在资源允许时恢复 |

- GET 遇到 429、暂时网络错误、5xx 可有界重试（最多 5 次），遵守 Retry-After，并受本轮总等待时间约束。
- 上游创建 POST 不自动重试。取得公开 ID 后立即持久化；进程重启只恢复已知 ID 的查询 / 保存和明确尚未提交的本地队列。不确定的 no-ID 提交必须人工确认。
- 视频调度器独立于图片任务。当前支持 **单 backend、单 Uvicorn worker**；不要开启 --workers 多进程或 docker compose --scale backend。
- 仍在追踪中的任务禁止直接删除关联 Key、项目或任务；界面只提供“放弃本地追踪”，并说明不会上游取消 / 退款。
- 删除结果 / 项目时，SQLite 触发器先持久化记录对象键，再级联删除结果；维护任务每分钟尝试 R2 删除，失败保留对象键与 attempts，后续继续重试。
- 手工接管只验证原视频 Key 有权查询且任务 ID / 模型匹配。不要填写另一个任务来覆盖，不确定时联系上游核对公开任务记录。

### 历史数据库外键兼容

项目类型迁移会在同一事务中比较迁移前后的外键异常明细（表名、行号、父表、约束编号），保留既有孤儿记录，不自动删除历史图片或批次。只要产生新增异常就回滚并拒绝启动；即使异常总数不变，也不能用不同的异常替换原有异常。部署验收应核对迁移前后的异常明细摘要一致，而不是要求历史库原本不存在异常。
