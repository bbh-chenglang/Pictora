# 视频生成 API 对接文档

本文档面向调用方开发人员，说明如何通过 `https://sub.beibeihai.xyz` 或 `https://direct.beibeihai.xyz` 创建、查询和获取视频生成任务。本文档只覆盖视频接口，不包含生图接口。

## 1. 文档范围与接入信息

| 项目 | 内容 |
| --- | --- |
| 服务地址（任选其一） | `https://sub.beibeihai.xyz` 或 `https://direct.beibeihai.xyz` |
| 模型列表 | `GET /v1/models` |
| 创建视频任务 | `POST /api/v3/contents/generations/tasks` |
| 查询视频任务 | `GET /api/v3/contents/generations/tasks/{task_id}` |
| 数据格式 | JSON，UTF-8 |
| 任务模式 | 异步；创建成功只表示任务已受理 |

两个地址使用本文档列出的相同接口路径。将所选根地址配置为 `BASE_URL`，末尾不带 `/`，也不要附加 `/v1`。以下示例默认使用 `https://sub.beibeihai.xyz`；使用 `https://direct.beibeihai.xyz` 时只需更换 `BASE_URL`。API Key 和模型权限应在所选地址上验证；保存任务 ID 时同时保存创建任务使用的地址，后续查询使用该地址。

生产环境必须使用 HTTPS，并设置合理的连接、读取和总等待超时。不要把 API Key 写入前端代码、日志、URL、任务描述或错误上报内容。

本文档中的鉴权错误已在 `https://sub.beibeihai.xyz` 实测：未发送鉴权时返回 `401 / API_KEY_REQUIRED`，发送无效 Bearer Token 时返回 `401 / INVALID_API_KEY`。`https://direct.beibeihai.xyz` 的实际错误码和消息以响应为准。成功创建和查询视频需要有效 API Key；本文档不会使用真实付费 Key 创建任务。

## 2. API Key 鉴权

所有接口都使用 Bearer Token：

```http
Authorization: Bearer YOUR_API_KEY
Accept: application/json
Content-Type: application/json
```

API Key 可向服务方申请。服务地址、API Key、模型权限和额度均由服务方控制；模型列表应以当前 API Key 调用 `/v1/models` 的结果为准。

## 3. 查询可用模型

### 请求

```curl
# 也可设置为 https://direct.beibeihai.xyz
BASE_URL="https://sub.beibeihai.xyz"
curl "$BASE_URL/v1/models" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Accept: application/json"
```

### 成功响应（示例）

```json
{
  "object": "list",
  "data": [
    { "id": "seedance-2.0-933-720P（秒）", "object": "model" }
  ]
}
```

模型 ID 必须原样提交。模型名称中的能力编码可帮助客户端做前置校验：`933` 表示图片、视频、音频参考素材上限分别为 `9、3、3`；`903` 表示 `9、0、3`；`301010` 表示 `30、10、10`。这是命名规则的解析结果；最终可用模型、权限、时长和素材限制必须以当前 API Key 的模型列表及服务方实际响应为准。

## 4. 创建视频任务

### 请求

```curl
# 也可设置为 https://direct.beibeihai.xyz
BASE_URL="https://sub.beibeihai.xyz"
curl -X POST "$BASE_URL/api/v3/contents/generations/tasks" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -H "X-Request-Id: 8c9d9d24-0ca1-4a2e-9bbf-5c1e9c5d5f08" \
  -d '{
    "model": "seedance-2.0-933-720P（秒）",
    "duration": 5,
    "resolution": "720p",
    "ratio": "16:9",
    "content": [
      { "type": "text", "text": "一只橘猫在窗边慢慢回头，午后自然光，镜头平稳推进" }
    ]
  }'
```

`X-Request-Id` 是调用方自己的关联标识，建议每次创建请求都生成一个唯一值并记录。它便于在 POST 超时或响应丢失时与服务方排查，不能替代服务端返回的任务 ID，也不能保证服务端幂等。

### 受理响应（示例）

```json
{
  "id": "task_01JABC123456789",
  "status": "queued"
}
```

收到成功响应且有任务 ID 后，保存 `id`（某些响应可能使用 `task_id`），后续只查询该任务。创建响应的状态可能是 `queued`、`running` 等进行中状态。

## 5. 请求参数

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `model` | string | 是 | `/v1/models` 返回的完整模型 ID |
| `duration` | integer | 是 | 视频时长，单位为秒；具体有效档位以模型能力为准 |
| `resolution` | string | 是 | 常见值为 `480p`、`720p`、`1080p`；不要提交模型不支持的档位 |
| `ratio` | string | 是 | `16:9`、`9:16` 或 `1:1`，以模型支持范围为准 |
| `content` | array | 是 | 至少包含一个文本项，可追加参考素材项 |
| `content[].type` | string | 是 | 文本为 `text`；图片、视频、音频素材分别为 `image_url`、`video_url`、`audio_url` |
| `content[].text` | string | 文本项必填 | 视频提示词 |
| `content[].*_url.url` | string | 素材项必填 | 服务方可访问的 HTTPS 地址 |
| `content[].role` | string | 素材项建议 | `reference_image`、`reference_video` 或 `reference_audio` |
| `content[].name` | string | 否 | 便于错误定位的素材名称，建议唯一 |

参数错误时，不要通过不断重试解决；应根据 `param` 或字段路径修正请求。

## 6. 文生视频与参考素材示例

### 纯文生视频

```json
{
  "model": "seedance-2.0-933-720P（秒）",
  "duration": 5,
  "resolution": "720p",
  "ratio": "16:9",
  "content": [
    { "type": "text", "text": "海边日落，镜头从远景缓慢推进，画面自然稳定" }
  ]
}
```

### 带参考图片、视频和音频

```json
{
  "model": "seedance-2.0-933-720P（秒）",
  "duration": 8,
  "resolution": "720p",
  "ratio": "16:9",
  "content": [
    { "type": "text", "text": "保持人物外观一致，人物沿街行走，使用参考音频的节奏" },
    {
      "type": "image_url",
      "image_url": { "url": "https://cdn.example.com/reference-person.jpg" },
      "role": "reference_image",
      "name": "主角"
    },
    {
      "type": "video_url",
      "video_url": { "url": "https://cdn.example.com/motion-reference.mp4" },
      "role": "reference_video",
      "name": "动作参考"
    },
    {
      "type": "audio_url",
      "audio_url": { "url": "https://cdn.example.com/music.mp3" },
      "role": "reference_audio",
      "name": "背景音乐"
    }
  ]
}
```

素材 URL 必须满足以下条件：公网可访问、HTTPS、无需登录 Cookie、在任务执行期间不会失效、返回正确的 `Content-Type`。素材数量不能超过当前模型的限制。素材失败时，以响应中的上游错误码、错误消息和素材名称为准，不要自行推断原因。

## 7. 查询任务状态

### 请求

```curl
# 使用创建此任务时的服务地址
BASE_URL="https://sub.beibeihai.xyz"
curl "$BASE_URL/api/v3/contents/generations/tasks/task_01JABC123456789" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Accept: application/json"
```

### 进行中响应（示例）

```json
{
  "id": "task_01JABC123456789",
  "status": "running",
  "progress": 42
}
```

### 成功响应（示例）

```json
{
  "id": "task_01JABC123456789",
  "status": "succeeded",
  "progress": 100,
  "content": { "video_url": "https://cdn.example.com/result/task_01JABC123456789.mp4" }
}
```

只有状态为 `succeeded` 或服务方明确记录为完成，并且存在非空的 `content.video_url` 时，才可以认为生成成功。`HTTP 200`、`progress=100` 或任务 ID 存在都不能单独代表成功。

## 8. 获取和保存视频结果

拿到 `content.video_url` 后，应在有效期内下载到自己的对象存储或业务存储，并保存任务 ID、模型、创建时间、完成时间、结果 URL、下载状态和文件校验值。结果 URL 可能是临时地址，不能作为永久业务链接。

下载失败时，先重新查询原任务并重新读取 `content.video_url`；不要重新创建生成任务。若 URL 已失效或服务方返回结果缺失，保留原任务 ID 并联系服务方排查。

## 9. 失败、取消和过期状态

| 状态 | 含义 | 调用方处理 |
| --- | --- | --- |
| `succeeded` / `completed` | 已生成 | 读取 `content.video_url` 并下载 |
| `failed` | 生成失败 | 读取 `error.code`、`error.message`、`param` 后修正或排查 |
| `cancelled` | 任务被取消 | 不要当作成功；确认是否允许重新创建 |
| `expired` | 任务已过期 | 停止轮询；按业务规则决定是否重新发起 |

失败响应示例：

```json
{
  "id": "task_01JABC123456789",
  "status": "failed",
  "error": {
    "code": "reference_asset_unavailable",
    "message": "参考视频无法访问",
    "param": "content[1].video_url"
  }
}
```

如果上游只提供错误码而没有具体原因，原样保留错误码，并明确显示或记录“上游未提供具体失败原因”；不要改写成提示词错误等未经证实的结论。

## 10. 轮询示例

```python
import time
import requests

# 使用创建此任务时的地址：sub.beibeihai.xyz 或 direct.beibeihai.xyz
BASE_URL = "https://sub.beibeihai.xyz"
HEADERS = {"Authorization": f"Bearer {API_KEY}", "Accept": "application/json"}

for _ in range(60):
    response = requests.get(
        f"{BASE_URL}/api/v3/contents/generations/tasks/{task_id}",
        headers=HEADERS,
        timeout=(10, 30),
    )
    response.raise_for_status()
    data = response.json()
    status = data.get("status")
    if status in {"succeeded", "completed"}:
        video_url = (data.get("content") or {}).get("video_url")
        if not video_url:
            raise RuntimeError("任务已完成但缺少 content.video_url")
        print(video_url)
        break
    if status in {"failed", "cancelled", "expired"}:
        error = data.get("error") or {}
        raise RuntimeError(f"视频任务失败：{error.get('code')}，{error.get('message')}")
    time.sleep(5)
else:
    raise TimeoutError("轮询窗口结束，请稍后继续查询原 task_id")
```

轮询超时只表示客户端停止等待，不代表上游任务已取消，也不表示可以重新生成。保存任务 ID，稍后继续查询。

## 11. 幂等与重复提交

创建接口是异步提交。若 POST 已发出但客户端遇到超时、连接断开、502、503 或非 JSON 响应，提交结果可能未知：

1. 不要立即再次 POST，以免产生重复任务和重复计费。
2. 使用保存的 `X-Request-Id`、请求时间、模型和参数联系服务方核对。
3. 如果服务方能提供任务 ID，从查询接口继续轮询。
4. 只有确认原请求未受理且业务允许重新生成时，才创建新任务。

## 12. 错误响应的统一结构

HTTP 层错误可能采用以下结构；字段会因接口和错误而不同：

```json
{
  "code": "INVALID_API_KEY",
  "message": "Invalid API key",
  "param": "Authorization",
  "request_id": "req_01JABC123456789"
}
```

客户端至少应保留 HTTP 状态码、顶层 `code`、`message`、`param`（如有）、`request_id`（如有）、请求路径和本地时间。任务查询成功但任务失败时，还要保留任务 ID、状态、`error.code`、`error.message`、模型和创建时间。

## 13. 生产接入清单

- 启动时使用当前 API Key 调用 `/v1/models`，校验模型确实可用。
- 所有请求都发送 Bearer Token 并使用 HTTPS。
- 创建任务前校验模型、时长、分辨率、比例和素材数量。
- 记录 `X-Request-Id` 和服务端任务 ID，不能记录 API Key。
- 将进行中、成功、失败、取消和过期状态分开处理。
- 只把有 `content.video_url` 的成功任务交给下载流程。
- 下载后校验文件大小、媒体类型和可播放性。
- 监控鉴权失败、参数错误、限流、5xx、任务失败率、轮询超时和下载失败率。

## 14. 错误处理

### 14.1 HTTP 状态码

| HTTP 状态码 | 常见含义 | 是否重试 | 应检查的定位信息 |
| --- | --- | --- | --- |
| `400` | 请求格式或业务参数错误 | 否 | `code`、`message`、`param` |
| `401` | 缺少或无效 API Key | 否 | `code`、`message`、请求使用的 Key 配置 |
| `403` | Key 无权限、模型无权限或资源被拒绝 | 否 | `code`、`message`、模型和账户权限 |
| `404` | 路径、任务 ID 或资源不存在 | 否 | 请求 URL、任务 ID、`code` |
| `409` | 状态冲突或重复操作 | 通常否 | `code`、当前任务状态 |
| `422` | 参数校验或素材校验失败 | 否 | `param`、字段路径、素材名称 |
| `429` | 触发限流或额度限制 | 查询可有限重试 | `code`、`message`、`Retry-After` |
| `500` | 服务端内部错误 | 查询可有限重试 | `code`、`message`、`request_id` |
| `502/503/504` | 网关、服务不可用或超时 | 查询可有限重试 | `request_id`、网络阶段、原任务 ID |

### 14.2 错误码和字段定位

客户端分支判断优先使用稳定的 `code`，面向人员展示 `message`。如果同时存在 `param`，它是最直接的错误位置，例如：

```json
{
  "code": "invalid_parameter",
  "message": "秒数必须是 5 到 10 之间的整数",
  "param": "duration"
}
```

处理顺序建议如下：

1. 记录 HTTP 状态码和脱敏后的 JSON 响应。
2. 读取顶层 `code`、`message`、`param`；任务查询响应还要读取 `error.code`、`error.message`、`error.param`。
3. 如果 `param` 是数组路径（例如 `content[2].image_url.url`），直接在请求对象中定位该项。
4. 未知错误码原样保存，不要映射成看似相近的已知错误。
5. 不要把网络超时、网关错误或下载失败误报成“生成失败”；应记录实际阶段：提交、查询或下载。

### 14.3 常见错误示例

鉴权失败（服务根路径实测响应示例）：

```json
{
  "code": "INVALID_API_KEY",
  "message": "Invalid API key"
}
```

缺少鉴权（服务根路径实测响应示例）：

```json
{
  "code": "API_KEY_REQUIRED",
  "message": "API key is required"
}
```

参数错误（结构示例，实际错误码和文案以响应为准）：

```json
{
  "code": "invalid_parameter",
  "message": "秒数必须是 5 到 10 之间的整数",
  "param": "duration"
}
```

素材错误（结构示例）：

```json
{
  "code": "reference_asset_unavailable",
  "message": "参考图片无法访问",
  "param": "content[1].image_url.url"
}
```

素材上传到上游通道失败（调用方网络或上游连接异常，结构示例）：

```json
{
  "code": "video_material_upload_failed",
  "message": "素材上传到官方通道失败：网络连接中断，请稍后重试",
  "param": "content[1].image_url.url",
  "stage": "material_upload"
}
```

此错误应记录素材名称、素材 URL 的域名、网络异常类型和原任务关联标识；如果任务尚未创建，可以在确认没有上游任务后重试素材上传。如果任务已经提交，先查询原任务，不要直接重新生成。

素材尺寸错误（结构示例；常见于图片宽高或像素总数不符合模型限制）：

```json
{
  "code": "invalid_parameter",
  "message": "像素数必须介于 407696 和 8295044 之间",
  "param": "content[1].image_url"
}
```

限流（结构示例）：

```json
{
  "code": "rate_limit_exceeded",
  "message": "Too many requests",
  "retry_after": 10
}
```

任务失败（结构示例）：

```json
{
  "id": "task_01JABC123456789",
  "status": "failed",
  "error": {
    "code": "upstream_generation_failed",
    "message": "上游未提供具体失败原因"
  }
}
```

结果下载失败（调用方本地诊断记录示例，不代表上游固定响应格式）：

```json
{
  "code": "video_download_failed",
  "message": "结果地址暂时无法下载",
  "param": "content.video_url",
  "task_id": "task_01JABC123456789"
}
```

下载错误应关联原任务 ID 并重新查询结果地址；不要重新创建视频任务。

## 15. 超时与重试

### 15.1 推荐超时

| 阶段 | 连接超时 | 单次读取超时 | 总等待建议 |
| --- | ---: | ---: | ---: |
| `/v1/models` | 10 秒 | 30 秒 | 45 秒 |
| 创建任务 POST | 10 秒 | 60 秒 | 75 秒 |
| 查询任务 GET | 10 秒 | 30 秒 | 30 秒 |
| 下载视频 | 10 秒 | 60 秒 | 按文件大小设置 |

视频生成是异步任务，创建接口不应等待视频生成完成。查询可采用 3–10 秒轮询间隔并设置最大轮询窗口。窗口结束后保存任务 ID，之后恢复查询。

### 15.2 哪些请求可以重试

| 请求 | 可重试情况 | 上限与策略 |
| --- | --- | --- |
| `GET /v1/models` | 网络错误、429、5xx | 启动验证最多 3 次，退避 2、4、8 秒 |
| 创建任务 POST | 只有明确收到 429 且服务方确认未受理时 | 默认不自动重试；超时或 5xx 视为结果未知 |
| 查询任务 GET | 网络错误、429、500、502、503、504 | 最多 4 次，退避 3、6、12、24 秒；优先遵守 `Retry-After` |
| 下载结果 URL | 网络错误、临时 5xx | 重新查询原任务后最多 3 次；支持断点续传时使用 Range |

使用指数退避并加入少量随机抖动，避免客户端同时重试。遇到 400、401、403、404、409、422 时不要自动重试，先修正参数、权限或任务 ID。

### 15.3 创建超时后的处理

创建 POST 出现客户端超时、连接重置、非 JSON 响应、502、503 或 504 时，无法确认上游是否已经受理。此时：

1. 将本地状态标记为“提交结果未知”。
2. 保存请求时间、`X-Request-Id`、模型、参数摘要和脱敏响应信息。
3. 不要自动再次创建。
4. 联系服务方核对是否存在任务；一旦获得任务 ID，转入查询流程。

### 15.4 查询和下载超时后的处理

查询超时不改变上游任务状态；继续使用原任务 ID 查询。下载超时不代表生成失败；重新查询 `content.video_url`，确认结果地址是否更新，再继续下载。只有任务明确进入 `failed`、`cancelled` 或 `expired`，才按任务失败处理。

## 16. 联系服务方排查时需要提供的信息

- 发生时间，注明时区；
- 接口路径和 HTTP 方法；
